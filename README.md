# Rcc Sherlock Autotests Junit

**rcc-sherlock-autotests-junit** - фреймворк для выполнения автоматизированного тестирования приложения "Личный кабинет андеррайтера "Шерлок" (ЛКА "Шерлок"), являющегося неотъемлемой частью проекта [РКК](https://confluence.psbnk.msk.ru/pages/viewpage.action?pageId=287791452). Функциональность данного фреймворка позволяет производить автоматизированное тестирование как front, так и back частей приложения ЛКА "Шерлок". Функционирование фреймворка обеспечивается технологическим стеком, описанным в разделе "Технологии".
# Технологии
- **[Autotest Framework](https://gitlab-01/automated-testing-technology/core_frameworks/fr-autotest-framework)** - библиотека, которая дополняет текущий функционал фреймворка в виде базовых классов и методов, необходимых для оптимальной реализации функционала данного фреймворка.
- **Java 11** - язык программирвоаниия, используемый для реализации кастомных методов и классов проекта, которые являются уникальными и не отражены в библиотеке Autotest Framework.
- **Selenium** - инструмент, позволяющий автоматизировать взаимодействие с веб-интерфейсом приложения, выполнять раличные действия и проверки.
- **Selenide** - фреймворк на основе Selenium, который упрощает написание методов для последующего их использования в автотестах, предоставляя более простой и удобный API.
- **JUnit** - фреймворк для запуска тестов и обеспечения проведения модульного тестирования отдельных методов проекта для контроля их корректной работы, а также для проверки реализации бизнес-логики в тестируемом приложении.
- **Spring Framework** - предоставляет механизмы управления зависисмостями между компонентами проекта автоматизации тестирования, что позволяет эффективно организовать структуру проекта, а также делает его более гибким и легко расширяемым.
- **RestAssured** - предоставляет удобные методы для отправки HTTP-запросов к REST API и проверки полученных ответов, что позволяет тестировать функциональность API ЛКА "Шерлок".
- **Gradle** - инструмент автоматизации сборки и управления зависисмостями в проекте.

# Техническое описание
## Структура проекта

Проект автоматизации тестирования rcc-sherlock-autotests-junit делится на два модуля **web** и **back** (временно не используется). Ниже приведена основная структура для модуля web:

### web
- **_web/src/main/java/ru.psb.autotestframework_** - основной пакет, содержащий компоненты фреймворка для модуля _web_:
    - **dataprovider/DbProperties.java** - класс, содержащий параметры, а также вспомогательные методы для подключения к БД ЛКА "Шерлок".
    - **pages** - пакет, содержащий файлы page object'ов, где содержаться элементы страниц тестируемого приложения.
        - _BasePage_ - класс `BasePage` является базовым классом для всех страниц приложения. Он расширяет класс `BaseActions` и реализует следующие интерфейсы:
            - `IDateSteps<T>` - определяет методы для работы с календарями и датами.
            - `IDropDownListSteps<T>` - определяет методы для работы с выпадающими списками.
            - `IScrollSteps<T>` - определяет методы по умолчанию для работы с прокруткой страницы.
            - `ITableSteps<T>` - определяет методы по умолчанию для работы с таблицами.
            - `ITabSteps<T>` - определяет методы по умолчанию для работы с вкладками.
            - `IFieldSteps<T>` - определяет методы по умолчанию для работы с полями ввода.

            Класс `BasePage` служит в качестве базового класса для всех страниц приложения, предоставляя общие методы для работы с данными, выпадающими списками, таблицами, вкладками и полями ввода.
    - **steps** - пакет, содержащий базовые классы и интерфейсы с методами по умолчанию, которые реализуют базовые шаги тестовых сценариев в ЛКА "Шерлок".
        - **_actions_** - пакет, содержащий базовый класс и интерфейсы с методами по умолчению, риализующие базовые действия с элементами страниц (проверка ожидания, состояния элемента, базовые действия с элементами), а также используемые в реализации шагов.
            -  _BaseActions.java_ - класс `BaseActions` является базовым классом для определения действий на страницах приложения. Он реализует следующие интерфейсы:
                - `IElementOperations<T>`- определяет методы по умолчанию для выполнения операций с элементами страниц.
                - `IElementWait<T>`- определяет методы по умолчанию для ожидания состояния элементов страниц.
                - `IElementState<T>`- определяет методы по умолчанию для проверки состояния элементов страниц.
            
                Класс `BaseActions` служит в качестве базового класса для определения действий на страницах приложения, предоставляя общие методы для работы с элементами и проверки состояния страниц.
        - **_asserts_** - пакет, содержащий класс `Asserts`, реализующий соответствующие методы для проверки утверждений.
        - **_dbApiSteps_** - пакет, содержащий классы для взаимодействия с основными объектами и сущностями ЛКА "Шерлок" посредством API и БД.
            -  _ActionsClaimSteps.java_ - класс для определения шагов, связанных с действиями над заявками.
            -  _ApiServiceSteps.java_ - класс для определения шагов, связанных с вызовами API-сервисов.
            -  _DbSteps.java_ - класс для определения шагов, связанных с работой с базами данных.
        - **_elements_** - пакет, содержащий интерфейсы, которые определяют методы по умолчанию для взаимодействия с элементами страниц, таких как поля ввода, вкладки, выпадающие списки, таблицы и другие.
    - **utils** - пакет, содержащий вспомогательные классы.
        -  _Attachments.java_ - класс, содержащий методы, реализующие дополнительный функционал, позволяющий выгружать скриншот тест-кейса в момент его падения.
        -  _ClearingQueueClaims.java_ - класс, реализующий функционал для очистки очереди заявок в ЛКА "Шерлкок".
        -  _Constants.java_ - класс для хранения констант.
    - **BaseTest.java** - класс `BaseTest` является базовым классом для всех тестовых классов в модуле web. Расширяет класс `BaseUITest`. Основная цель класса `BaseTest` - предоставить единую точку входа для всех тестовых классов, обеспечивая автоматическое внедрение зависимостей, инициализацию страниц и управление жизненным циклом тестов. Это позволяет избежать дублирования кода и обеспечивает последовательность в организации тестов.
- **_web/src/test/resources/data.json_** - пакет, содержащий json шаблоны для формирования и создания заявок в ЛКА Шерлок.
- **_web/src/test/resources/testit.properties_** - файл, содержащий настройки взаимодействия с TMS testIT
- **_web/src/test/resources/framework.properties_** - файл, содержащий общие нстройки фреймворка.
